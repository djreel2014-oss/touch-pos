## What Touch POS is
A touch-screen point of sale for Windows 10 and 11. It is a single HTML page (src\app\index.html) that runs in its own window using the Edge engine built into Windows, and works offline. From 1.4.0 all data is kept in a SQLite database (C:\ProgramData\TouchPOS\touchpos.db, or src\Data\touchpos.db when not installed) through a hidden PowerShell helper, with automatic daily backups and files saved to C:\ProgramData\TouchPOS\Files by default.

Main features: selling page with custom product layouts per staff member, several people on one order, supervised customers limited to one box item at a time with an override code, customer profiles with photos, QR and NFC credentials, Apple Wallet pass files (unsigned), receipts and PDFs, staff PINs and temporary PINs, idle lock, two-monitor customer display, import and export (JSON, ZIP with photos, CSV).

## Files in src

- README.txt: the readme shipped with the program.

## Version 1.4.0: SQLite customer database (2026-11-26)
DJ reported the database import not working. Tested in hidden Edge: CSV and JSON parsing worked, but the page kept everything in browser storage, which refused about 8 MB (QuotaExceededError). Customers with pictures overflowed it, and saves failed silently, so data was lost on restart. Pictures from sites without CORS headers were also blocked.

The fix keeps the project's languages (JavaScript and PowerShell):
- touchpos-helper.ps1 runs hidden on 127.0.0.1 port 47615. It uses winsqlite3.dll, the SQLite built into Windows 10 and 11 (both System32 and SysWOW64), through P/Invoke, so nothing is installed.
- Tables: kv (products, sales, settings, payment links, devices, staff, layouts as JSON) and customers (id, pos, name, email, phone, photo_url, photo BLOB, photo_type, data JSON, updated). Pictures are stored as BLOBs.
- Every request except /ping needs the key in helper.key (in the data folder). The launcher's helper adds it to the page address as ?k=, and the page remembers it in localStorage as tpk (the display window uses that).
- The helper opens the Edge window itself once the database is ready, using TP_BR, TP_URL, TP_HASH and TP_ARGS set by Start-TouchPOS.cmd. If a helper is already running it just opens the window. If the helper can't start, it still opens the window without the key and the app falls back to browser storage with a warning.
- Endpoints: /ping, /status, /get?n=, /set?n=, /clear, /fetch?url= (downloads a picture, fixes Google Drive and Dropbox share links, refuses web pages, 20 MB limit, TLS 1.2), /quit.
- The app already had a window.posStore hook in ld and sv; db-store.js provides it with synchronous requests. Customer pictures are sent only when they change (unchanged ones go as db:keep).
- On first start with an empty database, data already in browser storage is copied in, so 1.3.0 data carries over.
- After an import, pictures download automatically (it used to ask first), through the helper, and are saved in the database.
- The installer and uninstaller ask a running helper to stop first (/quit).
- Log: helper.log in the data folder.

Tests passed, all without windows: helper endpoints, the key check, unicode names, db:keep, picture download and error messages. Full app in hidden Edge: imported CSV and JSON, 2 pictures saved and 1 bad address reported, and after a reload in a fresh browser profile all 3 customers and pictures came back. 1,000 customers with pictures (40 MB): first save 2.8 s, everyday save 0.6 s, load 0.5 s. Launcher settings checked with a dummy helper. Installer unpacked: all 14 files match src.

Not tested: a real window, a real install over 1.3.0, and NVDA. Saves are synchronous, so with very large customer lists each customer change pauses the page for about half a second.

## Version 1.4.1: import fixed for real member lists (2026-11-26)
- DJ reported the import still not reading files. DJ had 1.4.0 installed and its helper running. The file was the club list on the Desktop (salim claude project\data.csv, 375 members, private, never sent anywhere). Its columns are First name, Last name, Nickname, Status, Email, Phone, Mobile, Address, Probationary safety, Shoot unaccompanied, 8-ring group signed off, Signed off by, Left, Hello Club id and Photo URL. The old reader only knew a column called name, so every row was dropped ("No products, customers or sales found"), and Photo URL was not recognised.
- New reader (impCustomer and helpers in index.html): column names are normalised (lowercase, non-letters to underscores) and matched against alias lists (IMPA). Name is the name column, or first plus last name. Delimiter is detected (comma, semicolon, tab, pipe). Encoding is detected (UTF-8 with or without BOM, UTF-16, Windows-1252). JSON can be a plain array or wrapped (customers, members, data and others); nested objects are flattened.
- Mapping for the club file: Hello Club id becomes extId (the app's own POS-xxxxxx id stays, because credential scanning needs that format). Shoot unaccompanied gives certBy and Probationary safety gives certDate, and either one marks the member as cleared. A Status containing "probation" without a sign-off means requires supervision. 8-ring group signed off and Signed off by give ring8Date and ring8By. Dates are read day first and stored as yyyy-mm-dd. Status, Nickname, Mobile and Address are stored as fields and also summarised in notes.
- Merge now matches by extId, then by email, so re-importing updates members.
- If no names are found, the error lists the columns it saw.
- Tested in hidden Edge against a separate test database on port 47699 (TP_PORT, test only): the real file as CSV, as semicolon UTF-16 and as JSON all gave 375 customers, 370 picture addresses, 102 cleared, 30 requiring supervision and 77 with 8 ring. The real Import screen with a 5-member sample saved 5 pictures to the database, and a second import updated 5 with no duplicates.
